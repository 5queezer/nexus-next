# Nexus rewrite: spec

Status: M1, M2 (section 9a) and M3 (section 9b) built. Installed on the board on 2026-11-07, tailnet only, with no cutover: old Nexus stays the system of record. Still the owner's to run: the M1 gate through a real ingress, real Telegram through Hermes, a real voice session, a phone, entering real CV facts and locking them.
Baseline: `nexus-crm` at `235138d`, the commit in the running production image's tag on 2026-11-06. Sources marked **[handoff]** are not yet checked against the code or the Nexus skills.

## 1. Goal

Replace the Next.js Nexus with one Rust binary on a ROCK 4 SE: an MCP tool server for agents, with a read-only web dashboard for humans. The live system stays the system of record until the M1 gate passes.

## 2. Decisions

| Decision | Choice | Consequence |
|---|---|---|
| CV rendering | Typst, from M2. M1 has no renderer | `CvProfile` and `CvPatch` are empty in production and no stored CV came from `generate_tailored_cv`. See section 4. |
| Data storage on the board | Root filesystem, outside `/home`, with encrypted off-site backups | Nexus restarts unattended after a reboot. Data sits unencrypted on the NVMe if the board is taken. |
| Host | ROCK 4 SE, subject to the Ethernet check in section 10 | |
| Auth | Keep OAuth 2.1 in v1, alongside API tokens | Port the authorization server, consent flow and a login page to Rust. Needs a public endpoint. |
| Scope | Single user. Drop email scanning, assistant tables, share links, demo workspace | `ScannedEmail` has no rows in production, so there is nothing to archive or import. |
| Hosting of this repo | Private, on Forgejo | Spec and integrity rules stay off public hosts. |

Reactive Resume stays usable for real applications until M2 **[handoff]**. Typst source editing (`patch_cv` and friends) also stays in M2.

## 4. MCP contract

`contract/mcp-tools.snapshot.json` holds real `tools/list` output for all 35 tools, generated from source at `235138d`.

1. **Serve the frozen schemas verbatim.** Embed the snapshot's `inputSchema` values instead of generating them from Rust types. Generated schemas would drift in small ways, such as `nullable` encoding and `$schema`. The golden contract test confirms the served schemas match.
2. **Golden test.** CI compares the server's `tools/list` with the snapshot, byte for byte and in order, then the rest of the list with `contract/mcp-tools.additive.json`. Any difference fails the build. A client now sees 40 tools: the 35 frozen ones, then 5 additive.
3. **Keep the quirks.** Limits differ per tool, and clients may depend on that:
   - `source` has `maxLength: 100` on `upsert_application_by_job_url` and `update_document_metadata`, but no limit in the schema on `create_application` or `update_application`.
   - `rating` is an integer on create and upsert, but a number on update.
   - `update_application` advertises lifecycle fields, then rejects them.
4. **Lifecycle rule.** `update_application` with any of `status`, `appliedAt`, `lastContact`, `followUpAt` or `currentStage` returns `{"error":{"code":"lifecycle_event_required","fields":[...]}}` as a tool error, and nothing is written.
5. **Confirm against production.** The snapshot was generated from the deployed commit, not read from the running server. Compare it with a live `tools/list` once before freezing.
6. **`generate_tailored_cv`.** The tool keeps its frozen schema and response. With no profile it returns old Nexus's exact tool error, `No CV profile found. Use upsert_cv_profile first.`. With one, it renders with Typst as section 9a describes. M1 alone returned a tool error here, and that gap is closed: what remains different is the PDF's bytes and so `size`, and that the document carries a `contentHash` where old Nexus left it null. Two new errors old Nexus could not return, `cv_fact_violation` for what a reader would see otherwise than the owner reviews, and `cv_approval_required` once the facts are locked and the wording isn't what the owner approved, can't affect current data, because production has no profile.

Runtime behaviour the schemas don't show is covered by the parity scenarios in `parity/`. The `nexus-job-intake-interview-pipeline` skill listed these from real use. This table is what the parity run against old Nexus's code at `235138d` found:

| Behaviour | Expected |
|---|---|
| Mixed metadata and lifecycle call | Fails atomically, applies nothing |
| `idempotencyKey` without `occurredAt` | Rejected with `occurred_at_required_for_idempotency` |
| Event `metadata.outcome` over 255 chars | Rejected, though the generic metadata schema doesn't show the limit |
| Document `source` over 100 chars | Schema error |
| Application `source` over 100 chars | Truncated silently to 100 UTF-16 units by `create_application`, `update_application` and batch. `upsert_application_by_job_url` rejects it by schema |
| `jobContentHash` not 64 hex chars | `upsert_application_by_job_url`: `{"error":{"code":"jobContentHash_invalid"}}`. `create_application`: plain text `jobContentHash_invalid`. `update_application`: `application_update_failed`. `batch_upsert_applications`: the whole call fails with `Batch upsert failed`. Over 64 characters is a schema error. Uppercase hex is accepted and stored lowercase; `""` and `null` store null |
| Local-offset timestamps | Depends on the field. Schema error: `lastContact`, `followUpAt` on create, `occurredAt`, `submittedAt`, and `expectedUpdatedAt` on update and events. Converted to UTC: `appliedAt` on create, `archivedAt`, `expectedUpdatedAt` on archive and unarchive, and metadata `scheduledAt` and `followUpAt`. Clients should send `Z` |
| Omitted `remote` | Reads back as `false` |
| Creating a record at `applied`, `interview`, `offer` or `rejected` with absent or `""` `appliedAt` | Any create path sets it to the current time. `inbound` stays null. An explicit `appliedAt` is always kept |
| Event tools without `mcp:submissions` | No scope needed: `list_application_events` and `list_application_activity` are allowed, including `application_submitted` events. Submissions, recall, `pipeline_healthcheck`, submission documents and deleting applications are blocked with `insufficient_scope` |
| Submissions | Concurrent idempotent replay, atomic document claims, immutability, aggregate payload limits, scope enforcement on exact answers |

## 5. Data model

SQLite (WAL, foreign keys on) with blobs on the filesystem.

| Prisma model | New table | Changes |
|---|---|---|
| `Application` | `applications` | Drop `userId`, `isDemo`, `demoWorkspaceId`, `demoKey`. `canonicalJobUrl` becomes unique on its own. |
| `ApplicationEvent` | `application_events` | Same drops. `idempotencyKey` becomes unique on its own. Keep `contactId` as text, as it is today. |
| `Contact` | `contacts` | None |
| `Document` | `documents` | Drop `userId`, `demoProvenance` |
| `_ApplicationToDocument` | `application_documents` | Explicit join table |
| `ApplicationSubmission` | `application_submissions` | Drop `userId` |
| `CvProfile` / `CvPatch` | `cv_profile` / `cv_patches` | Profile becomes a single row |
| `UserApiToken` | `api_tokens` | Starts empty: production has no tokens, so every current client uses OAuth |
| `McpOAuthClient`, `McpAuthCode`, `McpAccessToken`, `McpRefreshToken` | `oauth_*` | Start empty. Arrays become JSON text. |

Rules:
- **Keep integer IDs exactly.** Notes, skills and cron jobs refer to applications by ID.
- JSON columns become `TEXT CHECK (json_valid(...))`. Timestamps are UTC ISO 8601 with `Z`.
- Events can't be updated (`BEFORE UPDATE` trigger raises). There is no delete trigger, because `delete_application` and `batch_delete_applications` must still cascade as they do today, and SQLite fires triggers on foreign-key cascades.
- Documents linked to a submission are immutable, carrying over `isSubmissionDocument` from `lib/documents/access`.
- Blobs live at `blobs/<sha256>`. Check every stored `contentHash` during import.
- `documents.blob_sha256` locates the file in `blobs/`. It is separate from `content_hash`, which clients can overwrite or clear, so no lookup uses `content_hash`.

Dropped: `User`, `Session`, `Account`, `Verification`, `ShareLink`, `DemoWorkspace`, `AdminAuditLog`, `EmailIntegration`, `ScannedEmail`, `LlmCredential`, all `Agent*`, `ActionProposal`, `BulkCommand*`.

## 6. Auth

- Port `lib/mcp-oauth.ts` and `app/api/mcp/{authorize,register,token}`: dynamic client registration, PKCE S256, single-use codes, hashed tokens, refresh rotation, scopes `mcp:tools` and `mcp:submissions`, and the sensitive-consent version.
- Token routing stays by prefix: `mcp_at_` is OAuth, anything else is checked as an API token.
- better-auth goes away, so `authorize` needs a new login: one owner passphrase (argon2id) with rate limiting, a session cookie and the existing consent step from the `authorize` route.
- The logged-in owner changes the passphrase at `/passphrase` by giving the current one, which counts on the login backoff. A change revokes every OAuth grant and the API token and ends every session, and applies without a restart. The browser that made it is marked as the owner's again, so that an attack on the login backoff for everyone can't keep it out. `nexus set-passphrase` on the host stays for a lost passphrase.
- rmcp's `auth` features look client-oriented, so assume the authorization server is hand-written in axum. To verify at scaffold time.
- Hermes Career Ops also connects with OAuth (`auth: oauth` in its config), not only Claude.ai.
- Registration is open, because Claude.ai registers itself. So a redirect URI must be https to a host in `NEXUS_OAUTH_REDIRECT_HOSTS` (default `claude.ai,claude.com`, Claude.ai's real host still unverified) or loopback (`127.0.0.1` or `localhost`; `http://[::1]` stays refused, as in old Nexus), checked at registration and again at authorize.
- Rate limits and login backoff key on the client's address. With an https base URL, `serve` refuses to start until `NEXUS_TRUSTED_IP_HEADER` names the ingress's client-address header or says `none`. The header is believed only from `NEXUS_TRUSTED_PROXY_PEERS` (default loopback). Of a list or several header lines, the last entry counts: the one the ingress appended, so one ingress per instance.
- OAuth clients re-register after cutover if the issuer URL changes, so Claude.ai and Hermes would each need one reconnect. Keeping `nexus.vasudev.xyz` doesn't avoid this unless tokens and clients are migrated, and the OAuth tables start empty. Plan one re-authorization at cutover.

**Importer rules from this data:**
- `contentHash` is null on 35 rows, including 3 with files. Compute it for internal integrity and record that it was computed, but keep returning null to clients until one writes a value, as old Nexus does.
- Unconfirmed rows import with `blob_state = 'missing'`, not as if the file exists.
- `get_document` returns normal metadata for them, and only `download_document_content` fails, both as in old Nexus (confirmed by the parity baseline).

**Response compatibility.** Responses keep the fields clients see today even though the model is single-user: `userId` is the imported owner's ID, `isDemo` is false, `demoKey` and `demoWorkspaceId` are null, and `filename` is unchanged.

**Documented difference.** Above 1 MiB, production's `download_document_content` returns a signed GCS URL. The new server has no object store and returns content inline.

**Old Nexus backups.** The bucket also holds `_nexus-backups/pre-deploy/` (62 snapshots, 53 objects) and 14 unreferenced root objects. Review these for retention and secrets when decommissioning.

**Import:**
- One idempotent command that loads the owner's rows only and skips `isDemo` and `demoProvenance` rows.
- It fails on row count, hash or foreign-key mismatches.

**Parity gate:**
- For every application: `get_application`, `list_application_events`, contacts, documents and submissions return the same content from both servers, allowing only for documented differences.
- Writes go to a copy, never to live: replay recorded calls and compare responses and readbacks.

**Parity result, 2026-11-06, M2.** Golden scenarios of 1,809 calls through the real `nexus serve` binary, compared with old Nexus at `235138d` restored locally: 1,808 pass, 1 fail (`sort: company`), none documented. `generate_tailored_cv` now compares exactly except `size`, and `tools/list` must be the frozen list followed by exactly the additive contract. The M1 run had 1,805 pass and 3 documented for the same calls. That one is an artifact of the baseline: it ran under glibc `en_US` collation, while production compares bytewise (`'Z' < 'a'` is true there), as Rust does. Contact and linked-application order is compared unordered, because old Nexus returned Postgres heap order, which no client can rely on. About 18,000 further fuzzed calls matched apart from explained differences. The baseline goes stale for time-dependent `pipeline_healthcheck` checks from 2026-11-09, so re-record it after that.

**Cutover:** stop writes to old Nexus, re-export, import, re-run parity, then repoint clients. Keep old Nexus stopped but restorable for 30 days. The runbook is [`CUTOVER.md`](CUTOVER.md).

## 8. Deployment and open risks

**Board, read on 2026-11-06.** ROCK 4 SE, 6 cores, aarch64, Armbian 26.11.0-trunk (Debian 13), kernel 6.18. Armbian trunk is a development image, so expect kernel changes. RAM is 3.8 GiB with about 1.8 GiB available, alongside Coolify, Forgejo, CLIProxy and Joplin. NVMe root has 66 GiB free. `/home` is on a LUKS partition that stays locked after reboot, and was locked when read.

**Storage.** SQLite and blobs live on the root filesystem under `/var/lib/nexus`, never in `/home`, so the service survives an unattended reboot.

**RAM.** Target 30-60 MB at idle **[handoff]**. Measured on the board on 2026-11-06 at `0d5b5d8` with synthetic fixtures: 6.8 MB after start, 12.7 MB after 500 requests including 200 MCP calls, tool calls about 10 ms, binary 12.8 MB. With the real data set on x86-64, an earlier measurement before MCP was merged: 7.5 MiB after start, 29 MiB peak under 16 parallel clients. At `ab910ed` with `synchronous=FULL`, also on the board with synthetic fixtures: 13.2 MB peak, and 100 sequential `create_application` calls took 46.6 ms each including `curl` start-up. The real data set hasn't been measured on the board. M2 was measured on the board on 2026-11-06 at `3ca11bb` with synthetic data, arm64 musl binary 43.4 MB. The render worker peaked at 16.5 MB for text only, 36.7 MB for 2 pages with PDF and 1 PNG, 38.4 MB with 2 PNG, and 48 MB for 9 pages with 9 PNG. `serve` used 10.0 MB idle and 11.3 MB after 20 requests. Timings haven't been measured there yet.

**CV work on the board, 2026-11-07, at `379a52e`,** through the real unit's limits and sandbox, with invented data. A patch took 0.58 s on a 1-page CV, 1.24 s on 3 pages and 3.65 s on 10. A page load with its review took 0.80 s, 2.12 s and 6.26 s. Four page loads at once on 10 pages took 11.96 s. The whole cgroup, server and render worker, peaked at 73 MiB, against `MemoryHigh=256M`, and the server's `VmHWM` at 80 MiB. So the worst case read off a workstation, a server at 142 MiB beside a worker at its limit, wasn't seen here, and per-page image files aren't needed yet. A source built to reach the limits was not measured on the board.

**Backup.** `nexus backup` writes one age-encrypted file from a `VACUUM INTO` snapshot and the blobs it references, on a systemd timer (`deploy/README.md` section 6). The off-site destination is undecided.

**Durability.** `Db::open` sets `synchronous=FULL`, because an acknowledged submission must survive power loss: under `NORMAL`, a reboot can silently undo writes an agent already reported saved. QA's cost, on an x86-64 desktop NVMe (btrfs, 2 pinned cores) through real MCP, `NORMAL` then `FULL`: one agent p50 0.59 then 1.60 ms, p99 6.15 then 17.84 ms, 1,324 then 341 writes a second. Eight agents flat out: p50 1.65 then 11.72 ms, p99 34.50 then 333.20 ms, 2,430 then 348 writes a second, slowest single write 5.4 s against a 10 s busy timeout. Reads are unchanged. The board has not been measured, and real load is a tiny fraction of this. FULL does not cover a drive that lies about flushes. Real power loss has not been tested. `journal_size_limit` is 64 MiB: a checkpoint truncates a WAL grown past that once it restarts. The WAL can still grow beyond it under sustained load.

**Ingress: must be tested, not assumed.** Claude.ai needs a public URL.
- A Cloudflare tunnel keeps a stable custom domain, but local notes say the Cloudflare proxy breaks MCP streaming unless buffering is disabled.
- Tailscale Funnel avoids Cloudflare, but the hostname becomes `*.ts.net`, so clients change URL once.
- M1 gate: a full Claude.ai OAuth and tool call through whichever one is chosen.

**Limits.** Each kind of caller has its own pool of request slots: public (login, OAuth, calendar: 8 in flight, 2 s wait, 10 s deadline), owner (dashboard, JSON API: 8, 10 s, 60 s) and mcp (8, 10 s, 60 s, or 300 s for a large body). A full pool gives a 503. On the MCP route, a body over 1 MiB or of unknown length, and any `download_document_content` or `render_cv_pdf`, also needs one of 2 large slots, because one 10 MiB document costs about 85 MB in the transport. A batch holds at most 20 messages and at most 2 calls of those two tools, whatever the size of its body. `upload_document_content` takes one file of up to 10 MiB, and refuses it once all documents together would pass 1 GiB, counted from the sizes in the database. At most 256 connections. Details in `deploy/README.md` section 7.

**Calendar.** Calendar apps can't send bearer tokens, so `/calendar.ics` needs a secret URL token. Google Calendar fetches subscriptions from its own servers and can't reach a tailnet-only URL. Use an on-device subscriber such as ICSx5, or publish the URL through the public ingress.

**Availability.** The board's logs for 2026-11-06 show a reboot at 00:15 (cause unknown), then the Ethernet link down from 00:26:39 to 00:49:07 (cause unknown) with the board still running. LAN, Tailscale and the Cloudflare tunnel all failed together, taking Forgejo and CLIProxy with them. The current host, `hetzner-hel`, stayed up throughout. Nexus would inherit this failure mode on the board. Agents need a clear error when Nexus is down, and no parallel tracker.

## 9a. M2 design: Typst and dictation

**Voice stays outside Nexus [handoff].** Tier 0 dictation is Telegram voice note → Hermes transcribes → Hermes calls `patch_cv` → Hermes sends the PNG preview back. Nexus has no Telegram code and no bot token. "Dictation works" means these tools plus the Hermes skill text in [`DICTATION.md`](DICTATION.md) and `SKILL-CHANGES.md`, tested by a scripted MCP client through real OAuth and the real render child (`crates/server/tests/cv_dictation.rs`). A real Telegram run needs the owner and the deployed server.

**`crates/tailor`, the `nexus-tailor` library.** It embeds Typst and owns rendering and the integrity check. No other crate touches Typst.

- **World.** Only three virtual files exist: `/main.typ` (the revision's source), `/facts.json` (what a CV can render: name, contact, employment, education, languages, metrics. Not `banned_phrases`, which a source could read back from the violation, nor `allowed_tokens` and `vocabulary`, which could then change under an approved revision: an approval's hash covers exactly what this file holds) and `/nexus.typ` (the read-only template library, embedded in the binary). No filesystem, network, packages or system fonts. `datetime.today()` returns none. Fonts are a small embedded OFL set, chosen for binary size.
- **Templates.** `/nexus.typ` draws a source in one of five designs, named in the source's own setup line: `#show: cv.with(template: "modern")`. `classic` is the default, and a source that names none renders as it did before there was a choice. `modern` is a sans-serif page with headings in capitals, `banner` puts name and contact on a coloured band across the top, `sidebar` moves the header and every section holding `#skills` or `#languages()` into a dark side column, and `compact` is a dense black-and-white page. An unknown name is a compile error that lists them. Every helper works in every template, so switching changes that one line, and the Edit view's template select changes exactly that: it rewrites only a setup line written as `#show: cv` or `#show: cv.with(...)` with `lang` and `template`, in the editor's text, and leaves any other to the editor. The preview beside the editor then draws the text as it stands, typed or chosen, stamped and through the check, from `POST /cv/variants/{variant}/try`, which stores nothing; the normal save stores it. Without the script the select's own button stores the saved source in that template as a draft. A design is part of what the owner approves, since a changed source is a new revision. Fonts are Libertinus Serif and Inter, four files each, 1.7 MB more in the binary for Inter. Two limits of `sidebar`: the rendered text is rebuilt line by line across the page, so the side column's lines stand between the main column's in the text a review compares, while the picture is unaffected; a `#show` or `#set` rule at the top level of the source wraps what follows it, so sections after one stay in the main column; and a side column longer than the page is not continued on the next.
- **Layout notes.** Every compile also says how the pages are filled: the page count, how full the last page's text height is, about how many more lines it takes, and a list of things to look at, each with its kind, page, line and a sentence saying by how much. The kinds are `stub` (a wrapped paragraph, bullet, contact line or entry header whose last line holds one word or under 15% of its widest line; for an entry's company and title beside its date the note says so, and by how many characters the header is too long for one line), `headingAlone` (a section heading that is the last line of a page), `entrySplit` (an employment, education or project entry a page break cuts) and `thinLastPage` (a last page under 25% full or holding one line). They are advice: `RenderedText.layout` crosses from the worker beside `places`, no check reads it, nothing stored or hashed for an approval holds it, and nothing refuses on it. `patch_cv` and `render_cv_pdf` return it as `layout`, with the first 20 notes, and the Review view lists it under the words to check, each note marking its line in the picture. An approved head is not compiled for its review, so it shows none there. Headings and entries are found as elements, entries through marks `/nexus.typ` puts around them, which is exact. Which lines are one wrapped paragraph is read from geometry alone: a line continues the one above if it starts at the same left edge in the same size and its first word would not have fit above. That misses most wrapping in `sidebar`'s side column, whose width it can't see, and takes two separate lines for one paragraph if the first happens to be full. The fill assumes the text area ends as far from the bottom edge as it starts from the top. The templates keep a heading with what follows it, so `headingAlone` shows only for a source that undoes that. Contact details that need two lines are shared out evenly between them, so that none stands alone.
- **Page target.** A source can say how many full pages the owner wants: `#show: cv.with(pages: 1)` or `pages: 2`, set by hand, by an agent's `patch_cv`, or by the Pages select beside the template select, which works the same way. It draws nothing, so a source with it renders as the same source without it. The layout notes then start with a `pageTarget` note that says how far off the CV is: lines over and on which pages, lines short of full, the room on the last page, or that it is met once the last page is over 90% full, and `layout.targetPages` carries the number. Getting there is the agent's or the owner's work in steps: the notes only measure. The target is read from the setup line as the template is, so a setup line written another way has none. In the Edit view the preview of the editor's text lists the same notes under the picture.
- **Density.** `#show: cv.with(density: n)`, n from -2 to 2, draws the same text looser or tighter than its template: 4% of the text size, 10% of the line spacing and 10% of the top and bottom margins for each step, with the body text never under 9 pt, or under its template's own size if that is smaller, and the small text never larger than its template's. 0 is the default and is written as no argument, so a source without it renders as before; another number is a compile error. It is there to close a gap of a few lines to a page target without cutting text, and an agent can set it with `patch_cv`. The Edit view's "Fit to the pages" button asks `POST /cv/variants/{variant}/fit`, which compiles the editor's text at each density, five compiles at the most, with no pictures and storing nothing, and gives the text back at the best one for the editor to hold unsaved: a last page over 90% full with the least change, else the fullest last page at the target's page count, else the closest, with a sentence saying that no density reaches the target and how many lines are over or missing. A density at which the text fails the check is passed over. A changed density is a changed source, so it is a draft for the owner to read like any other.
- **From a rule to its words, and from a word to the source.** In the Review view each rule in the legend marks all its words in the picture while it is pointed at or focused, and dims the other words in the list; a click, Enter or Space keeps them marked, opens the folded part of the list if some are in it and brings the first into view in the list and in the picture, each within its own pane, until another click, Escape or a click elsewhere. Each line of the list and each layout note has an Edit link to `?view=edit&find=<word>`: the editor opens with the first whole-word occurrence selected, in any case, or with a line saying that the word comes from the facts or the template, with the way to the facts page. All of it is the page's script reading `data-rule` and `data-boxes`: nothing stored, hashed or approved changes, and the button still waits for the end of the list.
- **Source editor.** In the Edit view the source is a plain `<textarea>`, the form's field and the only holder of the text, and `editor.js` builds on it without any library: a coloured copy of the text lies under the textarea, whose own text is clear, and a column of line numbers stands beside it. Lines don't wrap, as before, so a number always stands at its line. A small tokenizer for Typst as a CV uses it colours comments, `#` code with its arguments and strings, content blocks, headings, list marks, strong, emphasis, raw text, math, escapes, labels and references; a quote that is never closed ends with its line, and code that runs into a `#` or a heading gives up to markup, so one missing bracket doesn't colour the rest. After a `#` a list offers the helpers of `/nexus.typ`, which `tailor` names once in `HELPERS` beside the template help, with a test that fails when a helper is not listed. Inside `#employment("`, `#education("` and `#metric("` it offers the ids in the facts, each with a line that says whose it is and whether the source already uses it, and inside `cv.with(` and `#project(` their named arguments and the values of those with few. The page gives that data in the `data-complete` attribute of `#cv-editor`: an attribute is escaped like any other text, and no page has an inline script. Up, Down, Enter, Tab and Escape work the list, Ctrl+Space asks for it. Tab and Shift+Tab move the selected lines by two spaces, and Escape followed by Tab leaves the editor, which a hint under it says. Enter keeps the indentation and goes on with a list, brackets and quotes come in pairs, Ctrl+S saves through the form and Ctrl+Enter compiles at once. Every edit goes through the browser's own editing, so its undo takes each back. `POST /cv/variants/{variant}/try` answers a text that doesn't compile with the compiler's `diagnostics`; beside a Compile button the page says whether the preview is up to date, marks the first problem's line in the gutter and puts its message on a button that takes the caret there, until a text compiles again. From the preview to the source and back: a compile that draws pictures also asks the compiler, through the `typst-ide` crate of the same version, where `/main.typ` writes each placed word, and `/try` answers with every word's page, box and that place, counted as a browser counts, or none for a word the facts or the template library wrote. A click on a word in the Edit view's preview selects it in the editor, or shows the line that says it comes from the facts or the template, and the word at the caret is marked in the picture. If the picture is the stored revision's, the first click costs one compile of the editor's text; no route was added. Behind the editor's own choices stand the compiler's, from `typst_ide::autocomplete`: Typst's names, a function's arguments, the fields of a value. `POST /cv/variants/{variant}/complete` takes the text and the caret, with the form token like `/try`, and stores nothing. It reads the syntax and evaluates what the caret stands in, with no layout, but that is still the source's code, so it runs in the `__render` child with the same three files and the same memory limit, takes the one compile's place while it runs, and the whole call, waiting included, ends within 3 seconds with an empty answer, so no preview or save stands behind it for longer. The editor asks only when Ctrl+Space is pressed, or while a name after a `#` or a `.` is typed that its own list knows nothing for, 250 ms after the last key, one question at a time, and one answer serves while the caret stays in its word. Its choices come after the editor's own. Without the script the textarea is the editor it was. Nothing stored, hashed or approved changes.
- **Worker process.** Every compile runs in a child, `nexus __render` (same binary; handled before clap and the async runtime, so it stays out of `--help` and a compile runs in a plain process), with a cleared environment, JSON on stdin and a framed result on stdout. This keeps the server's RSS near M1's and lets a runaway compile die alone. The parent allows one compile at a time and kills the child on wall-clock timeout or when `/proc/<pid>/statm` RSS passes the limit. The child raises its own `oom_score_adj` to 1000, so the kernel takes it first. It doesn't call `setrlimit`: the unit's `SystemCallFilter=~@resources` forbids that. The unit gets `OOMPolicy=continue`. Tests in crates that can't name the binary use an in-process renderer, which is never used by `serve`.
- **Limits.** Source 256 KiB, 10 pages, each 200 to 1200 pt on a side as laid out, so `auto` counts too, PDF 10 MiB, 30 s wall clock. A page outside that is a compile error: A3 is 842 by 1191, a page far longer than wide once left the stamp nothing to show in, and one too small has no room for a stamp a reader can read. The RSS limit is 128 MiB. Its real ceiling is `MemoryHigh=256M`, not `MemoryMax`: above it the kernel kills nothing but stalls every task in the cgroup, the server included. So the limit, the server's own peak of about 85 MB and what a compile can allocate between two 20 ms polls (about 45 MB seen) must fit below it.
- **Diagnostics.** A compile error is data, not a failure: `{severity, message, file, line, column, endLine, endColumn, hints}`. Agents see it in the tool result. Users never do. The worker keeps the first 20 errors and 20 warnings, 5 hints each, and 1,000 characters of each text.
- **What crosses to the parent.** The worker refuses a PDF and previews over 12 MiB together and rendered text over 1 MiB as JSON, so the parent reads at most 14 MiB from it, and kills a child that sends more. The rendered text stays bounded because `#panic` of a long string, or a page of numbers, could otherwise fill the reply and the server. These replies are bounded with it: `cv_fact_violation` and `reviewItems` list the first 50, 200 characters of each text, with a `truncated` count, and one page of `list_cv_revisions` carries at most 1 MiB of diff.

**The integrity gate.** Word and number rules can't tell a true sentence from a false one: an independent review put false dates, counts, titles and degrees through them with ordinary text, while they refused "Mentored junior developers". So the gate is this: **locked facts have one writer, and no agent-written text can reach an output without the owner seeing it and approving exactly that text.** Agents and voice edit wording freely. What they write stays a draft.

1. **Facts have one writer.** Nothing reachable from MCP or voice can change locked facts, or lock or unlock them. Owner-only paths lock, unlock or edit them: `nexus cv-facts` on the board and the dashboard's facts page, through the same functions in `repo::cv_facts`. Those record a `cv_facts_history` row, and so does an unlocked `upsert_cv_profile` that changes a fact, as `changed_by: mcp`, so that nothing an agent wrote in that window is lost.
   - `nexus cv-facts show` prints the facts to the owner's terminal.
   - `nexus cv-facts set --file facts.json` replaces the fields a profile can't express (`languages`, `metrics`, `allowedTokens`, `bannedPhrases`, `vocabulary`). Anything else in the file is refused. Employment, education, name and contact change through `upsert_cv_profile` while unlocked.
   - `nexus cv-facts lock` compares the facts and the profile's wording with the last lock and prints every changed field, old and new, quoted and escaped, and every URL in the wording that it would add to `allowed_tokens`. Wording compares by structural path (`skills[0].items[1]`, `experience[0:acme].tier`, `projects[0].url`), so a regroup, a moved string or a changed tier is a change here, in the hash and in `generate_tailored_cv`'s comparison. A lock made before these paths shows all its wording as changed once. The print escapes every value and path, so a control character in a job's id or a URL can't rewrite the owner's terminal. An id with control characters stays accepted, as old Nexus accepted it: the terminal is the only place it could do harm, and escaping there closes that without a new refusal on a frozen tool. If there is anything, which is always so at a first lock, it writes nothing and exits non-zero, naming a hash of that list: `nexus cv-facts lock --confirm <hash>` then locks. If anything was written since, the hash no longer matches, and it prints the new list and refuses. So an agent writing between the printout and the command is seen, not confirmed. It refuses while no profile has set a name.
   - The dashboard's facts page shows the same list, and its form carries the same hash. A lock from a page older than the last write answers 409 and shows the new list.
   - `nexus cv-facts unlock` opens them again. While unlocked, every revision is a draft.
2. **`upsert_cv_profile` keeps its frozen schema.** While facts are unlocked, it writes facts and wording as old Nexus would, so parity holds. While locked, a change to any fact field or a new `experience.id` returns `{"error":{"code":"cv_facts_locked","fields":[...]}}`, and nothing is written. Leaving `education` out counts as a change, since old Nexus reads that as empty. Leaving a job out of `experience` doesn't: it changes the profile's wording only, and the job's facts stay. Wording is free, numbers included: it reaches no output before the owner approves it. An unlocked write that changes a fact moves `version`, so that a compile which raced it can't store.
3. **`patch_cv` and `revert_cv` need locked facts, and so does anything stored from `render_cv_pdf`.** Otherwise: `{"error":{"code":"cv_facts_not_locked"}}`. So an agent can't first rewrite the facts through the profile and then patch to match them. A plain `render_cv_pdf`, which stores nothing, needs no lock, and always gives a draft while unlocked. Neither does `generate_tailored_cv`, as old Nexus had none: see below.
4. **Sources refer to facts by id.** The template library renders `#employment("acme")`, `#education("x")`, `#languages()`, `#contact()`, `#metric("key")` from `/facts.json`.
5. **The check reads rendered output, not source.** Typst can compute text and rewrite it with show rules, so a source scan proves nothing. After a compile, the worker extracts every text run from the laid-out pages, including white, tiny, clipped and off-page text and the content of tilings, and what the PDF says beyond its pages: title, author, description, keywords, date, heading bookmarks with their numbering, link targets and page-label prefixes. PDFs are untagged, so alt texts carry nothing. `hide` is a compile error, because Typst drops hidden text from the frames altogether, so the check could never see it. Only `hide`'s own rule marks text hidden, and that rule is what fails: a source's show rule on `hide` can only replace it, so its text is then drawn and read, or dropped from the PDF too. `pdf.attach` is a compile error for another reason: the PDF exporter attaches every element it finds, whatever a show rule did to it, and an attachment is text no page shows. So after each compile the worker asks the document for attachments, as the exporter does. Headings and attachments are the only elements the exporter reads that way. `nexus_tailor::check` then sorts what it finds into two tiers.

**Hard refusals** are never overridable by approval, and nothing is stored. They are precise, and they exist because a reader of the PDF would see something other than what the owner reviews, or the owner would be approving text that isn't all there is. Compile errors are refused the same way.

| Rule | Refuses |
|---|---|
| Banned phrases | Owner's `banned_phrases`, case-insensitive after Unicode NFKC, lookalike folding, closing up spaced letters and whitespace folding, across line breaks, and also where closing up spaced letters took the word gaps with it (`r o c k s t a r  n i n j a`), from word end to word end. Real phrases live only in the database, never in this repo |
| Images | Any image in the document, because an SVG or PNG can carry text the check can't read |
| Hidden text | Transparent (alpha under 0.3), under 4 pt along either axis, off-page, clipped or tiling-painted text, even if its wording would pass. Likewise a stroke over 0.1 em thick, which blots it. A glyph's ink must stand inside what shows, within 1 pt, not only its baseline. **A glyph a reader can't read on the drawn page, the owner's decisions of 2026-11-07:** see below |
| Missing letters | A letter the embedded fonts don't have, because it draws as a crossed box while the text reads as the letter. Refused under `missingGlyph`, naming the letter. They hold Latin, Greek, Cyrillic and Hebrew. In math they hold digits and no letters, so `$x$` is refused and `$1/2$` isn't. So is any symbol they lack, such as `✓`. Text naming a missing font falls back to an embedded one and passes. A control character draws a box too and isn't refused by this: it says nothing to read, and the picture shows the box |
| Bidi control | The characters U+202A to U+202E, U+2066 to U+2069, U+200E and U+200F in any run, read before normalizing removes them, and any run an override draws back to front. Typst trims a control from a line's ends while its effect stays, so the second test is the one that holds. Right-to-left scripts order themselves and pass |
| Transform | Text under anything but a translation and a uniform positive scale: rotated, mirrored, skewed or stretched, because a 6 turned is a 9. Likewise a glyph with a negative advance, because tracking draws `12` as `21`, a letter or digit advancing under 0.6 of its own width, because tracking of -0.46 em draws `1000` as `10` and well before that as a blot read as other digits, any other glyph under 0.05 em, marks and invisible characters excepted, any glyph over 1 em wider than its own width, because `1000` then reads as `1 0 0 0`, a word space narrower than 0.15 em, because spacing draws `1 2` as `12`, and a run standing on another's text by more than 0.2 em, because a PDF reader joins them. Word and line gaps use the size as drawn, and a run of only spaces counts by the gap it leaves, so digits set close together read as one number |
| Contact details | An email-shaped text, also as `name(at)host`, or URL-shaped text (a scheme, `www.`, or a host in a listed top-level domain: `com org net info biz eu de at ch uk dev app xyz example test`) unless it is the contact email, a page under the contact LinkedIn or GitHub, in `allowedTokens` or `vocabulary`, or in a fact. A phone number with a `+` or `00` country code, a space after it or not, other than the contact phone. Any link target but `http`, `https` and a `mailto:` or `tel:` matching the contact facts. A link showing a contact value that goes anywhere else: a link counts as showing all of every run it reaches into, and links side by side, or following one another with one target, as showing what they spell together. A URL or address in `allowedTokens` or a fact counts only whole: `docs.example.org/guide` allows neither `e.org` nor its parent host `example.org`. All upper-case `.NET`, `Node.js` and `socket.io` are not URLs. A lock adds URLs in the profile's wording to `allowed_tokens`. This is the one decision `allowed_tokens` still takes part in |
| Digit lookalikes | A word only of `l`, `I`, `O`, `З`, `О` directly before `%` or a time unit reads as a number and is refused: `lOO%`, `ЗО%`, `lO years`. `IO`, `I/O` and `CI` elsewhere stay ordinary words |
| Mixed script | One word mixing Latin with Cyrillic or Greek lookalikes, which has no honest use on a CV. Umlauts, wholly Cyrillic or Greek words and hyphenated parts of different scripts (`Москва-Berlin`) pass |

**What a reader can read is decided on the drawn page**, under `hiddenText`. Two decisions are the owner's, of 2026-11-07. Text covered by a shape is a hard refusal, judged by comparing pixels, because a copy of the renderer was wrong in four ways the fourth gate review found: a stroke's corners, a transparent paint, a gradient's stops, a large curve's flat edge. And light text is judged by whether a reader can see it against what it stands on, so white on a navy band is fine, and very pale text stays refused. How that is carried out, and every number below, is the coordinator's, and the owner's to change.

`ink.rs` draws each page four times with `typst_render`, one page at a time and before the stamp is added: as it really is, whole and with every run of text taken out, and the same two with hairlines widened as the harshest viewer draws them. Where a glyph's real outline says ink should be, the two of each pair must differ, so a glyph has to arrive in both: a viewer may draw either, and a paint only the widening draws is on no page. Nothing models what covers it, so a paint, a stroke, a clip, a gradient or a tiling all count by what they draw, and alpha needs no reasoning of its own.

- **The measure** is OKLab distance with chroma at half weight, with black on white about 1: plain sRGB distance rates pale yellow as plainly visible on white. **A reader can tell two colours apart at 0.16.** Measured on real glyphs on white: `#7dd3fc` 0.167, `#bbb` 0.195, `#c4c4c4` 0.172, against `#ccc` 0.146, pure `#ffff00` 0.12, `rgb(255,255,140)` 0.07.
- **Contrast.** A glyph's arrived ink, averaged at full coverage, must reach that, against whatever it stands on. So a navy sidebar with white or `#dfe7f2`, a dark header band, dark table headers, dark pills and a white letter in a navy circle pass, and text one step off its ground refuses in any colour. This replaces the old limit on luma and the rule against white text on a dark band.
- **Each glyph, by coverage.** A pixel counts as arrived if it changed by the contrast limit in proportion to how much of it the glyph covers, or, for text near that limit, by half of what its colour would change it by. Pixels a glyph covers under a quarter of aren't judged, which is where the renderer and the outline differ most.
- **Erased.** Lost ink whose place can't be told from the colour most of the glyph's box has, on the page as really drawn without its text: a white rect on white, black under white, an eraser inside a frame. **Over 5% of a glyph's ink is refused.** On 159 honest sources the most lost was 3%. The least a cover changes a letter by, measured: `e` as `c` 11%, `i` without its dot 14%, `ö` as `o` 17%, `A` without its crossbar 17%, `R` as `P` 17%.
- **Covered.** Lost ink that a reader can see something in place of, such as a black bar: **over 30% of a letter's or a digit's ink is refused.** A normal `#strike`, and 1 pt in red on 10.5 pt text, takes at most 23%, and on 8 pt text 28%. A bar reading `8` as `3` beside it takes 32%. A strike of 1 pt on text of 7 pt or under takes more, and is refused. Other glyphs aren't judged by this: a normal `#strike` covers all of a dash, and a line over a dash is still seen as a line.
- **Text over text.** All text is out of the second drawing, so a run over a run is judged by outlines: **over 33% of a glyph's ink under another run's glyphs is refused**, as black on black shows nothing to compare. The `3` of `$root(3, 27)$` has 15 to 25% under its root sign, by how its few pixels fall. Lines at no leading have 11%. An `8` over a `3` has about 70%.
- **The harshest viewer.** A PDF viewer widens a hairline to a whole pixel. Measured with poppler at 144 dpi: under white hairlines 0.25 or 0.5 pt apart, even 0.05 pt thick, a word is **blank**, while `typst_render` leaves it plainly readable, at any gap. So for this check only, the widened pair has every stroke and thin fill, text strokes included, at least 1.1 pixels wide along the narrower axis of whatever transform it is under, the smaller singular value, and dashes shorter than that closed up: a stretch doesn't enlarge a line's thickness when that runs across it, and poppler and Ghostscript still widen it. What the owner and a reader get is drawn as it is, and a ground or a dash closed up only there gives white text nothing to stand on and makes no eraser look visible, as the real pair judges those. A ghost is no help either way: what the check calls arrived has to be drawn at that width too. All 355 sources measured got the same verdict at 2, 3 and 4 pixels to a point, so it draws at the previews' 2.

The stamp can't refuse a draft, as it is added after the document has been read. The check runs wherever a source compiles: `patch_cv`, `generate_tailored_cv`, `render_cv_pdf`, the review and the approval. A source that can't be checked in the worker's 30 s and 128 MiB is refused, with no form and no approval. Measured on x86-64, for the whole worker through the real server, as a median time and a peak over 5 runs, against the two drawings before it (`9cbe93a`): a `patch_cv` with no pictures, 1 page 0.05 to 0.07 s and 40 to 55 MiB, 3 pages 0.13 to 0.19 s and 43 to 58 MiB, 10 pages 0.35 to 0.52 s and 56 to 65 MiB. A page load that also draws every picture: 1 page 0.09 to 0.11 s and 41 to 55 MiB, 3 pages 0.23 to 0.28 s and 45 to 58, 10 pages 0.66 to 0.85 s and 56 to 71. It hasn't been measured on the board. Each row counts what the worker's copy of the binary maps from the page cache, and another copy of the same binary, same bytes, read 6 to 9 MiB higher on every row: the heap is the same, 22 to 38 MiB on 1 page, and the limit watches the whole. A source written to cost as much as it can: 3000 near-transparent page-sized rects, 5 KB, took 18.3 to 18.6 s for a patch before, and now ends at the 30 s limit, refused. Ten full-text 1200 pt pages peak at 101 MiB, and 2000 tiny curves on each of ten pages at 127, or over the limit at 135 on that other copy, so near the limit a verdict can depend on the copy, always toward refusing. Past that a source ends at the 128 MiB limit, refused, as two sources that passed before now do, a curve of 100,000 points and one of many small curves: neither is a CV. The owner stands ahead of it.

**Review items** stop nothing. Each is `{rule, token, context, line}`, where `line` counts the lines of the rendered text from 1, and is null for what is no longer there. They are read on the lines that differ from the text last approved, because a line the owner has approved needs no second look, and a line that moved counts as changed, since a bullet moved to another job says something new. They come most serious first, with claim words ahead of new words and new words ahead of numbers: a whole CV lists every number, and a sentence nobody has seen stays in the open 30. A draft with over 30 new words has its numbers closed, under `The other N to check`.

| Rule | Lists, on a changed line |
|---|---|
| `missingFact` | A company, institution, language, metric, or contact value on the last approved text and not on this one. Line null |
| `entityBinding` | A fact's company or institution named outside its own entry: its full name, the name without a legal form (`GmbH`, `AG`, `Ltd`, ...) or its first word as written, without its exact title or qualification and date on that line or the next two. A year or date within two lines of it that isn't its own, another entry's full date anywhere up to the next one, and another entry's title or location within two lines |
| `languageLevel` | A fact's language with a level other than its own: `German (C1)` when the fact says C2 |
| `claimWords` | Degree, seniority and language-level words, in any case and after folding lookalikes and spaced letters, including abbreviations with dots (`b.a.`) and stems (`*leitung`, `fließend*`). The words of a fact standing whole on that line and `vocabulary` entries are that fact's, and aren't listed |
| `numbers` | **Every** number and date, whether or not a fact has it: an allowed number in the wrong place was the review's finding. Any Unicode decimal digits count, normalized, as do CJK numerals, Roman numeral signs, tokens mixing letters and digits (`S3`), and months beside a year in any order (`Nov, 2019`, `March of 2019`, `2019 March`). True contact values are masked out |
| `numberWords` | Spelled-out counts and scale words, in English and German, anywhere (`eight`, `zweieinhalb`, `eight-plus`, `Tausend`), and upper-case Roman numerals within three words of a time unit |
| `newWords` | A word, in any case, in neither the facts, `vocabulary`, the wording last locked, the text last approved nor the template's headings. That closes finding 12: a lower-case `google` is listed, and small caps are read as they are written |

Each word is listed once per line, under the first rule to name it, so a date near a company shows as `entityBinding`.

**Approval.** A revision is `approved` or `draft`, computed, never stored on the revision and never passed by a caller. It is approved when the rule below finds its `(source_sha256, facts_sha256)` in `cv_approvals` and the facts are locked.

- `facts_sha256` is a canonical hash of what `/facts.json` holds. `version` and `locked_at` aren't in it, nor `vocabulary`, `allowed_tokens` or `banned_phrases`, so an unlock and a relock with no change, or a vocabulary edit, invalidates nothing. Any changed fact invalidates every approval built on it.
- **An approval the owner has since replaced in a variant stops counting there.** A design choice, which the owner can overrule. A variant's newest approval by id, under whichever facts, decides: a text is approved there only if that row's source and facts both match. So a fact changed and changed back doesn't bring back what the owner corrected in between, and an approval under old facts is still no approval. A variant with no approval of its own takes a text that stands as the newest approval of some other variant, under these facts, as long as no variant has replaced it. That last part is the owner's decision of 2026-11-07: **a correction counts everywhere.** A variant has replaced a text if it held it and the owner has since approved another there, under any facts, whether or not it had an approval of its own for it, and until the owner approves that text there again. A `profileOverride` in a variant's first call doesn't count as replacing, as that variant never held the text, and nor does a fix two steps from the text, through a draft nobody tapped: `replaced_sql` reads one step back, and only `createFrom`'s parent. Nothing can tell a correction from tailoring, so approving a changed text in a variant counts either way: after it, a new variant holding the old text needs a tap. **The owner's decision of 2026-11-07, after the fifth review: a replaced text never gets a real PDF without a tap, also through the lock, but the review still shows what changed against the approved text the variant started from or last held.** So a plain `generate_tailored_cv` of a text a variant has replaced is a draft, for that same selection only, as another selection's text is another text, and a flow where nothing was ever replaced stays tap-free. That takes very little: the same jobs in another order are another text, with a lock row and a real PDF, no tap and no line. The way to end it is to correct the profile. A lock's own row stops counting too once its text is replaced: nobody tapped it, so that variant reads as a draft with the line, and one tap writes the owner's own row, which stands. **The cost, accepted by the owner:** a correction made elsewhere reads here as unchanged, so a line above the button says plainly that a text they approved has since been changed in another variant, and to read the picture. It also comes on a draft against a variant's own approval of that text, which reads the same way, and not where the correction was made or while the text stands. And after one tailored tap, every later application of that text takes one tap too, with that line. Other variants' own approvals the owner tapped are untouched. A variant made with `createFrom` and a change in the same call counts as having held the text it started from, so a fix made that way counts too, once it is tapped. A lock moving between two selections replaces nothing, since nobody corrected anything. So undoing drafts back to the newest approved text is approved at once, with no tap, as is `createFrom` of a text nobody has replaced and running `generate_tailored_cv` again. A `revert_cv` to older approved text is a draft, reviewed against the newest approval, and so is a new variant holding text that was replaced anywhere, or a render or a save naming an older revision by number: no path but a variant's own approval the owner tapped, which still stands there and can be saved to any application, makes a new real PDF of replaced text. A document stored earlier is a listed limit. The owner can approve it again, which makes it the newest and replaces the other.

**The stamp.** A draft renders only with `DRAFT, NOT APPROVED` across every page, in PNG and any PDF. A source can still choose what lies under it, so the stamp is translucent red with an opaque white outline: a page filled with the stamp's own red would hide one colour, and no fill matches both. A preview's cache key holds its state, so a stamp can't fall off a draft or stay on what was approved.

**Known limits.** The gate holds what it holds because a person reads the text. These stay:
- **The owner can approve something false.** That is the point of it being the owner. The highlights help, they don't decide, and a false sentence with no number and no new word in it shows only as a changed line.
- **`upload_document_content` is outside the gate.** An agent could upload a PDF made elsewhere and link it to an application. The frozen schema can't tell it from a real upload. `SKILL-CHANGES.md` carries the rule that a submission must only use a document made from an approved revision, which is an instruction, not an enforcement.
- **A stamped PNG can be forwarded.** So can a stamped PDF. The stamp says what it is, and that is all it can do. Someone could crop a corner of a picture or edit the PDF, since the stamp is drawn, not signed.
- **An approved source renders the same only for the same binary.** The key is source and facts, and a new Typst or a new template could draw the same text otherwise. `rendered_text` keeps what was approved, as data.
- **A review item is a highlight.** A date split over two lines is listed as its parts, and a word hyphenated at a line's end as two. A token a normalizer changed, like a dash in a date range, is listed but not marked in the diff.
- **A local-format phone number isn't refused.** It can't be told from a date range, so it is listed as a number. With a `+` or `00` country code it is refused.
- Text drawn with `curve` or many small shapes is no text to the check, like an image: only the picture shows it, along with the line about marks if it stands on or beside a glyph.
- **What the check of the drawn page doesn't refuse.** Nearly all of these show in the picture, which is why that comes before the button. **What doesn't show truly is a mark added to what's there: an added mark can make a number read as another, a `3` as an `8`, `15` as `1.5`, `5` as `−5`, an `F` as an `E`, in the picture and the PDF alike, while the text says the other. The owner's decision of 2026-11-07 is to warn, not refuse. So the owner has only this line and the picture:** above the button, a line says the draft draws marks on its text, naming the words, when the page without its text has a small paint on a glyph's box or within 1.5 pt of it. Small means under an em each way. Level pieces with more of their line beside them don't count, as an underline breaks around a descender and a dotted leader is all pieces, and nor does a short underline, at least three times longer than high under the baseline. So a mark over an em long, one more than 1.5 pt from the glyph, or a level bar with a decoy on its row, draws no line. Three real pale paints measured draw none either, and each shows: a pale 0.24 pt line under a comma, a white patch in a grey box around a letter, and a white patch on a band of stripes, where the page beyond is on the patch's row (`w3` b, j, l). Over 176 honest sources (`e1`, `e6`, `a2_honest`) it fired once, on math with a root sign, and a strike or an underline on one short word sets it off. An eraser taking up to 5% of a glyph's ink: a serif, or a part of a stroke, which measured changed no letter. A visible paint over up to 30% of a letter or digit: the bar itself shows, and `E` can read as `F` beside it. A visible line over a dash, a dot or other punctuation, which a normal `#strike` is too. A patch filling the glyph's box counts as erased, whatever its colour, as the colour most of the box has is then the patch's. Another run's glyph over up to 33% of one, such as `|` over `5`. White lines 1 pt or further apart, which chop a word and leave it readable, in poppler too, can pass, by how they fall on the pixels: under 1 pt they refuse, and 0.02 pt lines 1 to 3 pt apart over one word, measured, all refuse. A glyph drawn in `curve` or small shapes draws ink no check reads, as the previous limit says, and has nothing to cover: it shows in the picture, and as ink it can read as anything. A page gradient or tiling is judged where the text stands, so grey text passes on the pale end of a gradient and refuses on its dark end. Text at the limit of contrast is pale: `#c8c8c8` on white passes and reads with effort. These limits hold at 2 pixels to a point: on a page over A4 the check draws a little coarser, as the previews do, to stay under 2.2 million pixels. **The widening has been measured with poppler at 96 and 144 dpi**, and the fifth gate review measured Ghostscript, MuPDF and cairo on what it found: not PDFium or Acrobat. - `generate_tailored_cv` needs no lock, for parity with old Nexus, so while unlocked it can store a PDF built on facts an agent has just written. They show at the next lock, with their history, and the PDF carries the stamp.

- A parent killed outright leaves its child to systemd's cgroup kill. `OOMPolicy=continue` hasn't been exercised by a real kernel OOM kill.
- A client lost during a compile stops it, and nothing is stored. Lost after the compile, in the moments before the commit, the revision is stored with no one told, and a proxy may not pass on a disconnect at all. `expectedRevision` then refuses the retry, and `get_cv_source` tells.

## 9b. M3 design: PWA and voice

**No WASM.** The handoff said Leptos islands. M1 chose SSR without WASM, and M3 keeps that: server-rendered pages, working forms, and one small hand-written `/assets/app.js` for what forms can't do. That saves a second build target and a large download on a phone, at the cost of the handoff's stack word. It's a recorded change, not an oversight.

**PWA.** `manifest.webmanifest`, icons and `sw.js`. The service worker caches only static assets and one offline page: **never** a page or JSON response, because they hold personal data. Installable on Android Chrome.

**Interactive dashboard.** The owner can append a note, change rating and triage fields, record lifecycle events (the one way to change status), add a contact and archive. Forms call the same tool functions as MCP through one internal entry point, so lifecycle rules and validation can't diverge. Every POST carries a CSRF token signed against the session. Old Nexus's lifecycle rule applies: mixed calls fail whole.

Three things the forms do beyond the tools, none of which a tool can reach. Marking an application applied goes through `nexus_mcp::owner::mark_applied`: the same event, plus `applied_at` when it is empty and `last_contact`, in one transaction. Old Nexus's status control sets neither, and neither does the frozen `record_application_event`, so this goes past parity on purpose. It keeps a stage the application already has, as old Nexus does. `at`, the event's time, is set by `app.js` at the first submit, with the time the page was built as the no-JS fallback, and is refused more than 24 hours behind now or 10 minutes ahead, because it records a human action happening now. An identical contact on the same application is refused, since that form has no key to replay; `create_contact` and `batch_create_contacts` still add what they are given.

**CV workspace (`/cv`).** Variants at `/cv/variants/{variant}`, because `/cv/{variant}` couldn't tell a variant named `facts` from the facts page. `/cv` lists the revisions awaiting approval, and the top nav shows a small count while the facts are locked. A variant page has a draft or approved badge, the review items in plain language with the most serious first, the rendered diff with highlights on the changed lines, the source diff below, the stamped preview, an Approve button and the source editor, with revision list, diffs and revert. Besides those: `preview.png`, `preview.json`, `cv.pdf`, `approve` and `/api/cv/{variant}/head`. The facts page has lock and unlock, with the lock's list. Human edits pass the same hard rules, through the same code as `patch_cv`, and are approved by being saved there only if the base they started from was approved. Otherwise they store a draft. A `done` banner shows only when the head agrees with it, because an agent can send the owner a link with any query. Preview PNGs are cached in `<data>/cache/renders/`, which backups skip and anything may delete, emptied at start because a new binary may render or judge differently and the key can't see that. One file per render, not one per PNG.

**Live preview.** `GET /api/cv/{variant}/events` is an SSE stream of new revisions and approvals, fed by an in-process channel. An approval makes an open preview drop its stamp in place. `X-Accel-Buffering: no`, a heartbeat, at most 4 streams, ended at shutdown, and outside the owner pool's 60 s deadline. If the stream breaks, the page falls back to a slow poll.

The session is checked only at connect, so a stream lives at most 10 minutes, then ends and reconnects through the check. Any logout also ends every stream at once: a stream doesn't know its session, and a browser still logged in just reconnects, while the logged-out one gets a 401. The `head` event sent on connect carries the state as well as the revision, because an approval made during a gap is heard nowhere else. The page counts an approval as shown only once its fetch has succeeded, and a failed fetch starts the slow poll, since an open stream won't say it again. A timer in the stream can't free the slot of a client that stopped reading once its socket is full, since hyper then stops polling the body. So a watchdog outside the stream drops the connection 30 s after the stream's life ends, unless the stream ended first.
 A facts change sends no event, so an open page keeps its old preview until reload, and the check and the cache are still right at the next render.

**Voice session.** OpenAI Realtime over WebRTC, directly from the browser. The platform assistant extends the original CV-only scope: `/assistant` is reachable from the main navigation and uses a separate window so main-page navigation does not end the conversation. A session does not require a CV variant. Tap to talk, then tap to send is the default; holding Space is an alternative. Hands-free is opt-in: one connection path, not two systems. The UI shows the actual conversation phase separately from microphone state. Interrupt reply keeps the connection; End conversation turns the microphone off and preserves the visible transcript and activity. Starting a new conversation clears that local history.

1. `POST /api/voice/session`: owner session and CSRF; optional CV variant context. Nexus calls OpenAI with the key in force and returns a short-lived client secret plus a Nexus voice session id. The real key never reaches the browser. Without a key, the feature is off and the page says so.
2. The browser sets up WebRTC with that secret.

   **The key.** It comes from `NEXUS_OPENAI_API_KEY_FILE`, read at start, or from `/openai-key` (Account menu), where the logged-in owner sets or removes one by giving the passphrase again, which counts on the login backoff. A key set there wins over the startup file and applies from the next mint, without a restart; removing it falls back to the startup file. Before storing, Nexus opens one unused session with the new key: a 401 stores nothing, and any other failure stores nothing unless the owner ticks "store without checking". The key lives in `<data-dir>/openai-api-key`, mode 0600, replaced atomically, and in memory. It is never in the database, a backup, a log line, a response or an MCP tool: the page shows its last four characters and when it was set. A mint that OpenAI answers with 401 returns `voice_key_refused`, and the assistant links to `/openai-key` instead of asking to try again. Without a login (local mode) the page shows the state and takes no key.

3. The model's function calls arrive on the data channel. The browser runs those of a `response.done` whose status is `completed`, sending each to `POST /api/voice/tool` with the voice session id. A cancelled response is someone saying "no, don't".
4. **The allowlist is enforced by the server, on that route.** The session's tool definitions come from it too.
5. Every 20 s the page asks `GET /api/voice/status`, with the voice session id. Only the page can close the connection, and hands-free can send sound for up to an hour with no tool call. A 401, `voice_session_invalid` or `csrf_invalid`, here or from a tool call, ends the session: microphone off, connection closed, and the page says so. That covers logout and restart. A failed check (network error, no answer in 10 s, a proxy's error page) is no proof, but a server that stays out of reach can't enforce anything, so two in a row end it too. The route is outside the owner pool, so that a busy dashboard can't read as a lost server, and needs no CSRF token because it tells the page nothing else.

**Platform assistant gate (supersedes the original CV-only gate).** Voice may use an explicit server-side allowlist of existing internal application, event, contact, document metadata/link and CV tools. Existing MCP validation and lifecycle rules apply unchanged. Internal event records describe events explicitly reported by the owner, including historical submissions or contact; they do not send messages or submit applications. Permanent deletion, bulk destructive tools and external sending are denied. Unknown tool names are denied before dispatch. Tests must prove permitted changes persist and denied calls leave data unchanged.

**External-action boundary.** Outbound messages and automated application submission remain a separate experimental feature. Before enabling any real dispatch, require a reviewable preview, explicit authorization for the exact recipient/content, fake-transport end-to-end tests, duplicate-send prevention, and recovery when a timeout leaves delivery uncertain. No external dispatch tool is exposed by this implementation.

**Spoken response length.** Match the owner's request length, intent and urgency: short commands get a brief result, urgent clear commands act first, and longer explanations require a request or material need. Do not narrate routine tools or add generic follow-up offers. Never suppress an ambiguity, error or uncertain write outcome to appear concise.

**Voice can't approve.** It can patch, and the preview stays stamped. `voice_instructions.txt` tells the model it can't approve, that the owner approves on screen, and never to call a CV final unless `state` says `approved`. A CV tool call with no `variant` uses the session's selected variant. If the session has none, it must supply an explicit variant; it must not silently operate on `default`. An explicit variant is still honoured.

**Limits.** Client secret 60 s, 2 live sessions with the oldest evicted, 12 mints an hour including failures and reset by restart, tool body 1 MiB, session body 4 KiB, session length at most 3600 s. Settings: `NEXUS_REALTIME_VOICE`, `NEXUS_VOICE_SESSION_SECONDS`, and the hidden `--voice-test-base-url`, accepted only with `--insecure-local-only` and only as `http://127.0.0.1:<port>`. New codes: `voice_cv_variant_required`, `voice_argument_not_allowed`, `voice_session_invalid`, `voice_disabled`, `voice_rate_limited`, `voice_upstream_failed`, `voice_key_refused`, `voice_bad_request`, `voice_failed`, `csrf_invalid`, and in the browser only `voice_invalid_arguments`, `voice_network_error` and `voice_http_<status>`.

**Headers.** "No microphone elsewhere" is `Permissions-Policy: microphone=()` on every page from the web crate. The auth crate's login pages carry no such header, and load no script. With no key, the variant and assistant pages get that strict form too: no OpenAI in `connect-src`, no `media-src`.

**A conflict on save** re-renders with the new head as the base, so saving again replaces it. That is a choice made after reading the notice, and history keeps both. `Serve(Box<ServeArgs>)` in `main.rs` is what clippy required once the struct grew.

**TLS for the call to OpenAI: `hyper-rustls` with `ring` and `webpki-roots`, not `reqwest`.** `aws-lc` is what `reqwest`'s `rustls` feature pulls, and its `rustls-no-provider` unifies across the workspace and makes every `reqwest::Client`, test clients included, panic. **`ring` contains C and assembly**, against the letter of "no C beyond SQLite". It needs no system library and cross-builds, and it stays because the alternatives are alpha or young: `rustls-rustcrypto` and `graviola`, rejected unbuilt.

**Cost and data.** Sessions have a server-enforced lifetime (15 minutes by default) and an idle cut-off in the page. Everything the allowed tools return goes to OpenAI: this includes job descriptions, event notes, the owner's email address on events, and other people's contact details. `deploy/README.md` lists it. The owner opts in by creating the key file.

**Sandbox.** The unit's `IPAddressDeny=any` blocks the call to OpenAI, and OpenAI's addresses aren't stable enough to list. `deploy/voice.conf` is an optional drop-in that lifts the filter, and using voice means accepting that. Nothing else in Nexus makes outbound calls.

**What can't be tested without the owner:** a real Realtime session (costs money and sends data to OpenAI), a phone's microphone permission, and Telegram through Hermes.
